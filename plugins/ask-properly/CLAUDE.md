## Ask Properly Plugin

The ask-properly plugin lives at `plugins/ask-properly/`. It is one Stop hook, modeled closely on the sibling `link-all-refs`, `no-blame-language` and `no-busy-poll` plugins: a turn does not end while its closing message hands the user a decision in prose -- a question typed at them, or a deferral ("your call", "let me know", "want me to") that parks a choice the model was asked to make. The refusal is exit code 2 with each finding, the line it sits on, and the two ways out on stderr, which is how a Stop hook hands the model its objection.

**The incident this exists for**: a session resolving a spec's open questions was answered on one card and asked a question in the same message; it recorded the answer, wrote the doc, and never answered the question. Told "you didn't answer my question", it replied that it would not re-ask on a card since the last one was dismissed -- reading one dismissal as a standing prohibition. Told to do as instructed, it swung the other way and edited the file on its own judgment, resolving a design conflict the user had reserved. `AskUserQuestion` renders the options, so the user picks instead of composing a reply, and writing the options down forces the model to have thought them through. Prose does neither.

**The escape hatch is the tool, not the phrasing.** A turn that called `AskUserQuestion` is allowed to end however it likes: prose beside a rendered card is commentary, not an offloaded decision. The check is per TURN, not per session -- an `AskUserQuestion` in an EARLIER turn does not license a prose question now (`TestAnEarlierTurnsAskDoesNotCount`). Turn segmentation is ported from `no-busy-poll`: a new turn starts on every `type:"user"` record whose content is not entirely `tool_result` blocks, since a tool result answers a call from earlier in the same turn and must not split it.

**A "?" alone cannot decide this, and that is the whole detector.** This org's specs are full of nullable types (`Int?`, `raw_args?`) and every compare URL carries `?expand=1`, so matching a bare question mark reports a question in a message that asked nothing. `stripLinks` blanks markdown link destinations and bare URLs first (a query string is not a question), then `closesAQuestion` asks two things in order: does the mark END ITS LINE, ignoring trailing closers like a backtick or a paren -- a type annotation always has the thing it annotates after it -- or, failing that, does the sentence OPEN with an interrogative cue in its first two words. Two words, not more: "The field is Int? and ..." reaches `is` on the third word and is a statement, while "Is that a contract?" opens with one. Both halves are needed; an earlier draft matched a cue anywhere in the sentence and reported every nullable type in a paragraph that mentioned one.

**The deferral table is data, not code.** `deferralPhrases` is a plain `[]string`, so extending it is editing one slice. Each entry offloads a choice: `your call` and `let me know` park the work, `want me to` and `shall i` ask for permission already granted, `say the word` invents a confirmation gate the user never asked for. A message may state what it did and stop; it may not close by inviting the user to decide in prose.

**The refusal names both ways out, because a refusal that says only "do not" costs a round trip.** Answer it yourself from the code, the docs or a sensible default and say what you assumed; or call `AskUserQuestion` with the recommendation first and labelled, every option describing what it costs and what it buys, and every open question batched into one call. It also states that a dismissed or unanswered card is not a ban on asking -- that misreading is half the incident above. On `stop_hook_active` it escalates, and adds that deleting the question while leaving the decision unmade does not satisfy it.

Fenced code, indented code and blockquotes are exempt (ported from `link-all-refs/refs.go`'s `assertedText`), so this policy can be written down without tripping the hook; inline backticks are NOT exempt, matching both siblings. Every failure path allows the stop -- an unparseable payload, a missing or unreadable transcript, a message with no text, and any `hook_event_name` other than `Stop` -- because a guard that blocks because it could not read a file is worse than no guard.

- **Hook binary**: `plugins/ask-properly/hook.go` -- the Stop payload, the used-the-tool allow, the refusal text and its escalation
- **Detection**: `plugins/ask-properly/questions.go` -- the deferral table, the cue list, link stripping with offset tracking, the end-of-line/opens-with-cue rule, and the fenced/indented/blockquote exemption
- **Transcript**: `plugins/ask-properly/transcript.go` -- the last assistant message's text plus whether this turn called `AskUserQuestion`, read from a bounded tail
- **Tests**: `plugins/ask-properly/questions_test.go`, `hook_test.go`, `transcript_test.go` -- nullable types and compare URLs NOT tripping it, a real question and every deferral phrase blocking, the tool-used allow, an earlier turn's call not counting, a tool result not splitting a turn, and every fail-open path
- **Plugin config**: `plugins/ask-properly/.claude-plugin/plugin.json` -- one Stop hook registration

The prose half is `claude_snippets/answer-then-obey-never-sulk.md` in `PazerOP/claude-code-web-config`, which covers what this hook cannot see: the sulk when the deferral is called out, and the unilateral edit when the correction lands. Keep the two in sync if either changes.
